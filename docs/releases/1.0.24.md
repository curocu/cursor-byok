# Cursor BYOK 1.0.24 · Windows x64

本版汇总自上一次 GitHub 发布（1.0.6）以来已纳入当前源码的修复。安装包和免安装版见 [Windows 发布页](https://github.com/curocu/cursor-byok/releases/tag/windows-v1.0.24)。

## 启动、升级与桌面

- **升级过的数据库无法启动**。恢复原始迁移 `0013_cursor_capabilities.sql`，让运行过 1.0.25 / 1.0.26 的数据库可由 1.0.24 正常读取。保留历史迁移校验，覆盖 LF 和 Windows CRLF 迁移历史。
- **接管时 Cursor 会被关掉**。启用 BYOK 接管时复用已保存的代理端口并应用代理设置，移除主动终止编辑器的行为。
- **主题在重开窗口或端口变化后丢失**。主题保存在本地数据库中，重新启动时恢复；读取或保存失败在界面显示错误。
- **关窗重开丢失当前页面**。`×` 和 `Alt+F4` 隐藏到系统托盘，重新打开可恢复当前页面。通过托盘“退出”结束应用。

## Agent 执行和继续聊天

- **聊天发出后反复重连**。兼容 Cursor 在 `BidiAppend` 中发送的二进制载荷和原有十六进制载荷，覆盖连接、状态回复及流式结束。
- **更换 harness 后协议提取不完整**。移除提取脚本对压缩后变量名的假设，增加新旧命名的回归覆盖。
- **Task 子 Agent 启动失败**。补回 Cursor 客户端执行子 Agent 所需的配置和原生默认开关，覆盖空响应的有界重试、Explore / Debug 子任务、后台进度、等待和中断。
- **Plan 切换工具缺失**。补齐 Agent / Multitask 进入 Plan、Plan 切回 Agent 的目标配置，并覆盖原生 TODO 的参数和结果往返。
- **引导消息不能及时进入当前任务**。通过 Cursor 原生引导传递取消当前采样和工具写入的宽限参数；普通发送继续按 Cursor 自己的设置处理。
- **主任务停止后子任务继续运行或被重新请求**。同时识别请求头和请求正文携带的父子关系，关联原请求与重试，覆盖已运行和晚到的后代调用。向 Cursor 返回可识别的用户停止状态，正常完成的父任务仍可让背景子任务继续。
- **停止后继续聊天反复遇到工具 JSON EOF**。将已中断且未成功执行的历史工具转换为中断记录，保留已经完成的工具结果和最新用户消息。损坏的成功调用仍返回错误。
- **恢复含图片的历史时报告缺图**。支持 Cursor `Uint8Array` 十六进制图片和原来的 Base64 格式，恢复时保留原始字节和 MIME 类型。

## 模型目录、参数、上下文与摘要

- **刷新后官方或 Auto 条目重新混入菜单**。接管的模型目录只返回 BYOK 聊天模型和相应变体，清除旧的 Auto 入口配置，并保留其他服务端元数据。聊天模型用分组或提供商主机名标识来源。配置保存后可通过 Cursor 自带的模型列表刷新看到最新结果。
- **模型默认值与保存配置不一致**。目录使用保存的上下文和思考强度，保留思考菜单。`Default` 使用配置默认值，运行时明确选择的思考强度优先于保存时的额外参数；调用记录反映实际生效的强度。本次提供的温度和采样参数也优先于已保存的额外参数。
- **用量圆圈消失、上下文上限为零、缓存输入漏计**。启动元数据和每轮结果使用同一个有效上下文窗口，单独回传当前调用的上下文输入，包括相应缓存用量，供 Cursor 更新用量与压缩判断。
- **原生自动摘要缺少能力声明**。在握手和每轮结果中声明自摘要支持，让 Cursor 负责触发摘要、保存归档及继续执行。

## 流式输出、工具结果与失败提示

- **Responses 多段文字丢尾或重复**。按输出项和内容下标分别合并增量与最终快照，保留已显示的文字。回传及下一轮重放保留文字、思考、工具的顺序和多个加密推理块。
- **Claude 工具失败被当成普通结果**。保留 `tool_result.is_error`、关联 ID，以及文本和图片内容。提供商专用的思考状态只在相应通道重放。
- **输出达到 Token 上限时丢失已生成内容或发出半截工具参数**。三种聊天协议保留部分文字并回传 Cursor 可识别的输出上限状态；未完成的工具参数不会触发执行。
- **上游 401、429 等错误归因到了 Cursor 账号**。回传上游 HTTP 状态、安全的错误详情和 `Retry-After`，让 Cursor 区分模型密钥、限流、权限和过载。
- **网络几秒或几十秒失败却提示等待了总超时上限**。错误区分连接、响应头和响应体等阶段，显示实际经过时间。响应流截断保留可用原因，错误中的请求 URL 不会带回查询参数中的密钥。

## 图片生成与测试界面

- **配置了默认生图模型，Cursor Agent 仍收不到 `GenerateImage`**。修复 BYOK 的生图能力声明，在设置默认模型后向相应的 Agent 请求提供原生工具入口。
- **切换 Images API 和 Responses 生图后参数错位**。将已知图片参数移动到该协议应使用的位置，保留其他额外字段；旧配置发请求时也按当前协议整理。
- **同名生图模型难以区分**。默认模型和测试模型的选择菜单显示协议，模型 ID 与显示名不同时也会列出 ID。
- **测试只能使用固定描述，或临时参数影响默认设置**。在系统设置的图片生成页输入描述，临时选择测试模型和参数。失败和取消后保留输入，成功后可打开独立预览。尺寸、画质、格式、背景、审核、复杂度和压缩率均可按上游支持范围配置。
- **小窗口或较大系统缩放下，测试描述框被裁掉**。修复弹窗正文的滚动区域，可用滚轮、滚动条或键盘访问下面的字段。图片预览关闭后返回原测试弹窗。
- **生图错误与无效结果处理**。校验空图、损坏图片、不完整响应和无效选项，保留上游状态与安全类别；取消不会等待上游生成完成。
- **生图模型混入聊天和提交消息选择器**。生图模型单独配置，聊天目录和提交消息模型只使用对应的文本模型。

## 已移除的入口

当前版本移除了插件管理、外部 API 页面及其模型调用端点、使用教程和回复底部统计。聊天中的 “Routed to …” 展示沿用 1.0.6 的处理。途中曾交付的外部 API 配置和回复统计功能现已退出。

## 验证范围

- **本地测试**覆盖三种聊天协议、两种生图协议和上述回归场景。相关测试位于 [服务端测试](../../server/tests/) 和 [生图参数测试](../../apps/desktop/src/shared/utils/imageGeneration.test.mjs)。
- **真实运行记录**在 Cursor 3.31.15 的内置 harness 上确认了 Responses 聊天以及工具结果往返。
- **待验收**包括最新修复后的真实 Cursor 生图与保存、全套 Multitask 场景，以及新版本上的真实 Chat Completions 和 Claude Messages。Tab / FileSync 的 HTTP 525 和旧有可选缓存／签名字段的影响仍待单独核实。早期曾交付的 BYOK 父子参数补传也未在当前源码确认，子 Agent 的实际参数继承以原生运行记录为准。
